# Mechanics workspace

Open an entity in Library and choose **Mechanics**. Power systems, cosmology, organizations and custom entity types use the same rule model; no category forces a template.

Rules are grouped as Sources, Costs, Limits, Progression, Techniques and Exceptions. Add or edit a draft, filter by kind, or remove a rule with Undo. The shared contextual composer includes the open entity and its rules. Entity Sections remain available for arbitrary creative components and longer lore.

A scenario records a situation, expected outcome (works, fails, or open question), and the creator's own optional conclusion. Scenarios are hypothetical creative exercises, not automatic simulations. Local considerations flag missing structure, duplicate rule names, changed accepted wording and scenarios without conclusions; they do not judge fictional truth.

**Review for canon** shows the previously accepted wording beside the current draft. Accept applies only to that exact rule. Changed or archived rules cannot be accepted from a stale review. Migration 0010 preserves rule snapshots across edits and canon promotion; portable world and JSON exports retain them. Preexisting rules enter the history on their first edit or promotion.

Open a rule’s **History** menu to inspect saved snapshots and restore earlier wording as a new draft. This retains the current accepted canon. Portable worlds use format v6 (v1–v5 remain importable); JSON export is schema 9.

The assistant can propose rules and scenarios through the existing Review queue. No agent action can approve a rule or write the creator's scenario verdict. Subscription access and Manual-mode cancellation stay at the existing core boundary.

This is a structured rules studio. A spatial technique tree, automatic combat simulator, mathematical constraint engine, and canon branch merging are not implemented by this workspace.
