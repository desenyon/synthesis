## Conflict and queue procedures

- Root holds `Studio.swift`, `main.swift`, `WorkspaceStore.swift` shared surfaces, model serialization, `WorldArchive.swift`, migration numbering, aggregate capture registry, ledger, commits and source push. A child owns named new files and prearranged small hooks only. For simultaneous owner requests: reserve footprint in scratch, agree value types/signatures, use separate files, and have root/owner land the common hook sequentially. Coordinate Canvas bundle rebuilds with native bridge edits.
- For ~50 available seats, use one root, two coordinators (dependencies and evidence), six independent reviewers (native visual by size assigned separately as needed, data/migration, canon/privacy, focused functional regression), and up to 41 feature owners/scoped auditors drawn from the assignment map. The table enumerates overlapping data surfaces deliberately; launch research/design/checking concurrently, write only nonoverlapping files. Resume/replace assigned seats without exceeding supported concurrency. For ~4 slots: root build queue; one coordinator who can later move to feature work; one scoped implementation owner; one independent checker. Rotate during later milestones.
- A build ticket is a source hash/diff, owning agent, numbered IDs, focused inputs and exact output directory. Root freezes sources per build or confirms source revision at launch, runs `check.sh` and other requested commands sequentially, and routes logs. Native captures use verification bundle + disposable DB. Write no source while compiler packages it; pure report/independent inspection can continue. A later source change invalidates visual claims about affected surfaces until re-rendered.
- Reviewer works independently off the frozen diff and rendered output. Compare narrow, medium and wide states, and distinguish fixture wiring from real gesture evidence. State observable UI, rejection behavior, close/reopen persistence, Undo, import/legacy fixtures where relevant, and failed checks with dispositions. Only root changes statuses after reviewing per-item evidence.
- Protected boundaries: explicit proposal/canon decisions, scoped reads/permissions, archived references plus Undo, offline Canvas, persisted Manual/AI mode and subscription-only credentials. #375 owner decision is a real scope conflict. #388 physical/VoiceOver, #35 physical routing, and any live subscription evidence require separate go-ahead. Release/tag and public publishing are separate explicit owner actions.
